> **초안이다.** 팀이 확정하면 이 절과 [PLAN.md 15절](PLAN.md#15-업무-분담--기능--문서-v01)을 함께 고친다. 시간은 추정치이고, 이슈를 만들 때 각자 다시 적는다.

### 나눈 기준

- **0단계 기반 책임과 이어지게** 맡는다. B는 DB를 설계했으므로 SQL 비중이 큰 기능과 테이블 정의서를, C는 코드 구조를 짰으므로 관리자 기능과 메뉴 통합을, A는 문서 구조를 잡았으므로 문서 내용과 회원·가져오기 기능을 맡는다.
- **세 사람의 합계를 약 20h로 맞춘다.** 0단계가 가벼운 A가 기능과 문서를 더 맡는다.
- **다른 사람이 기다리는 일을 먼저 한다.** 로그인(A), 과정·수업일(C), 출결 규칙(B)이 먼저 머지되어야 나머지 기능을 실제로 돌려 볼 수 있다.

### 이 초안에서 바뀐 점 (PLAN 11절 기존 기능 분담 대비)

- **L-09 반 전체 현황: C → B.** 뷰, GROUP BY/HAVING, LEFT JOIN 등 SQL이 중심이라 DB를 설계한 B가 맡는다.
- **L-04 수업일 캘린더: A → C.** 관리자 기능(L-03과 같은 메뉴)이고, C가 관리자 계정이다 (PLAN 14절 8번).
- **ERD는 B의 기능 시간에서 빠지고 0단계로 옮겼다.**
- **스켈레톤 컴파일 오류는 0-C(C)에서 고치고**, A의 L-01·L-02는 아이디·비밀번호 방식으로 다시 쓰는 일만 맡는다.

## 10/23 (금) ~ 10/26 (월) 오전 — 개발 루프

```text
코드 작성 → PR 생성 → 리뷰·승인 → (승인된 PR 3건 이상) → 머지 회의 10분 → 머지 → 다시 코드 작성
   ↑                                                                                    │
   └────────────────────────────────────────────────────────────────────────────────────┘
```

| 단계 | 규칙 |
| --- | --- |
| 코드 작성 · PR | 각자 자기 이슈의 코드를 작성하고 PR을 만든다 ([CONVENTION 5절](CONVENTION.md#5-pr-rule)) |
| 리뷰 · 승인 | PR이 올라오면 나머지 두 명이 리뷰하고 승인한다. **두 명 모두 승인한 PR을 "승인된 PR" 1건으로 센다** |
| 머지 회의 | **승인된 PR이 3건 이상**이 되면 작업 중이라도 머지 회의를 연다. 약 **10분** |
| 머지 | 머지 회의 직후 머지한다. 한 건씩 머지하고, 뒤 PR에 충돌이 생기면 작성자가 최신 `main`을 pull해 해결한 뒤 다시 push한다 ([CONVENTION 2절](CONVENTION.md#충돌이-났을-때)) |
| 다시 작업 | 머지가 끝나면 최신 `main`을 받아 다음 작업을 이어 간다 |

**10/26 (월) 오전까지** 이 루프를 반복한다.
